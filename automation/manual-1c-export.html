Как вручную повторить выгрузку 1c-reports

Практическая инструкция по текущей программе. Сверено с её настройками и обработкой данных 2 октября 2026 года. Для каждой базы действия выполняются отдельно.

Программа берёт три отчёта 1С, полный журнал чеков и массовую выгрузку справочника дисконтных карт, затем объединяет данные в ровные таблицы. Отдельные карточки владельцев и телефоны для новой версии не нужны.

1. Подготовка и открытие отчётов

  1. Откройте нужную базу в браузере. Войдите пользователем IT, под которым созданы варианты отчётов. Пароль в эту инструкцию не включён.
  2. Выберите день данных. Например, запуск 01.10.2026 в 03:00 должен выгружать 30.09.2026. Во всех исходниках используйте один и тот же день.
  3. Если варианты не видны в меню, используйте надёжный способ: верхнее служебное меню 1С → Перейти по ссылке → вставить внутреннюю ссылку из приложения в конце инструкции → перейти. Ссылку e1cib/… вставляют в диалог 1С, а не в адресную строку Chrome.
  4. Ссылки на сохранённые варианты различаются между базами. Сначала откройте соответствующую базу, затем используйте ссылку из её блока.

В интерфейсе отчёты обычно доступны в разделах продаж и склада. Состав и названия меню зависят от базы; приведённые ниже внутренние ссылки — фактический маршрут программы. Варианты сохранены как личные для автора IT.

Общие действия для трёх отчётов

  1. Откройте нужный сохранённый вариант.
  2. Включите галочку Период. Дата начала и дата окончания — нужный день, например 30.09.2026 и 30.09.2026. Если видны часы, охватите весь день: 00:00:00–23:59:59.
  3. Снимите дополнительные быстрые отборы по магазину, организации, товару и т. п. Программа выгружает все магазины базы, а не только магазин, указанный в верхней жёлтой полосе.
  4. Нажмите Сформировать. Дождитесь исчезновения «Отчёт формируется…». Не сохраняйте старую таблицу, пока новый отчёт ещё строится.
  5. Сохраните полученный табличный документ: кнопка с дискетой / «Сохранить» → Лист Microsoft Excel 2007 (.xlsx) → ОК. Если предлагается установка компоненты для сохранения, используйте штатное Продолжить без установки, когда эта кнопка доступна.
  6. Дождитесь обычного файла .xlsx. Файл .crdownload означает незавершённую загрузку — переименование не завершает скачивание.

2. Итоговый файл «Продажи»

Результат: одна строка на магазин: «Дата отчёта», «Адрес магазина», «Выручка», «Чеки», «Алкоголь, ед.», «Количество возвратов», «Сумма возвратов, ₽», «Средний чек, ₽». Дата отчёта — день данных; в колонке адреса используется название магазина из 1С, как согласовано.

2.1. Выручка и чеки

  1. Выгрузите полный журнал чеков за день по инструкции в разделе 4.1. Сгруппируйте действующие чеки по магазину: отдельно сумму и количество продаж, отдельно сумму и количество возвратов. Статус «Пробитый» учитывается наравне с «Архивный»; отложенные и отменённые чеки не включаются.
  2. Посчитайте: Выручка = сумма продажи − сумма возврата. «Чеки» — количество продаж плюс количество возвратов. Сумму возвратов показывайте положительным числом.
  3. Средний чек = сумма продаж до вычета возвратов / количество чеков продажи. Например: продажи 10 000 ₽, возвраты 500 ₽, 10 продаж и 1 возврат → выручка 9 500 ₽, чеков 11, возвратов 1, сумма возвратов 500 ₽, средний чек 1 000 ₽. Если продаж нет, средний чек оставьте пустым. Общий средний чек считайте по общей сумме продаж и общему числу продаж, а не как среднее по магазинам.
  4. Для независимой сверки откройте Автовыгрузка - Чеки, задайте тот же день, уберите отборы, сформируйте и сохраните XLSX. Сверяйте итог магазина, не складывая его повторно с вложенными кассами и кассирами. Этот сводный отчёт может содержать только архивные чеки: в таком случае сравнивайте его с архивной частью журнала. Отсутствие в нём «Пробитых» не исключает их из ежедневных продаж.

2.2. Алкоголь

  1. Откройте Автовыгрузка - Алкоголь на основе отчёта «Продажи», сформируйте за тот же день.
  2. Проверьте группировки Магазин → Номенклатура.Алкогольная продукция. Под магазином возможны строки «Да» и «Нет».
  3. В строке Да возьмите Количество товаров. Именно это число попадёт в «Алкоголь ед. (продано)». Строка «Нет» и общее количество всех товаров сюда не входят.
  4. Если при корректной структуре отчёта строки «Да» для магазина нет, алкогольное количество — 0. Количество берётся в единицах данного отчёта, без самостоятельного пересчёта в литры.
  5. Соедините источники по точному названию магазина. Выручка берётся из полного журнала действующих чеков. «Сумма продаж со скидкой» из товарного отчёта служит дополнительной сверкой и не подменяет её.

Проверка: суммы магазинов должны совпадать с итогами соответствующих источников. При настоящем расхождении товара и чеков сохраните всю выручку и все действующие чеки, пометьте магазин как предварительный и запишите причину. Неподтверждённое количество алкоголя оставьте пустым. Один статус «Пробитый» сам по себе не является расхождением.

3. Итоговый файл «Остатки»

  1. Откройте Автовыгрузка - Остатки, задайте тот же день, снимите отборы, сформируйте XLSX.
  2. Структура исходника: Магазин → Номенклатура. Создавайте итоговую строку для каждой товарной строки внутри магазина.
  3. Название родительского магазина повторите в каждой его товарной строке. Строки итога магазина и общего «Итого» оставьте для сверки, но не добавляйте как отдельные товары.

Проверка каждой строки: начальный остаток + приход − расход = конечный остаток. Затем сверяйте суммы товарных строк с итогом магазина и суммы магазинов с общим итогом. Начальный остаток относится к началу дня, конечный — к концу выбранного дня.

4. Итоговый файл «Бонусы»

Этот файл показывает покупки с дисконтной картой. Сумма по карте — сумма чеков с её использованием за вычетом возвратов. Это не баланс бонусов и не сумма начисленных или списанных баллов. Текущая программа использует журнал чеков; одноимённый стандартный отчёт по дисконтным картам не заменяет всю эту процедуру.

4.1. Полный журнал чеков

  1. Откройте журнал Чеки через раздел продаж либо через «Перейти по ссылке»: e1cib/list/Документ.ЧекККМ.
  2. В «Ещё» верните стандартные настройки списка. Очистите отборы Магазин, Организация, Касса ККМ и строку поиска. В некоторых базах поля «Организация» нет — это допустимо.
  3. «Ещё» → Установить интервал → начало и конец нужного дня → подтвердить.
  4. Проверьте наличие колонки Операция. Если её нет: «Ещё» → Изменить форму → раскрыть «Список» → включить «Операция» → ОК. Это настройка отображения, не изменение чеков.
  5. «Ещё» → прокрутить меню до Вывести список. Выберите Текстовый документ, включите все колонки и снимите «Только выделенные». Нажмите ОК.
  6. Скопируйте весь полученный текст или сохраните его штатными средствами. При переносе в Excel используйте разделитель табуляция; номера карт задайте как текст, чтобы не потерять нули и длинные цифры. Не копируйте только видимые строки прокручиваемого журнала — список в браузере подгружается частями.

Нужные поля: Дата, Смена, № чека ККМ, Сумма, Статус, Операция, Дисконтная карта, Магазин, Касса (ККМ). Для распознавания непробитых документов используется также «Отчёт о розничных продажах», когда он присутствует.

4.2. Какие строки учитывать

  • «Аннулированный» — исключить.
  • Пустой статус — исключить как документ, предназначенный для удаления, даже если смена уже заполнена (согласовано 02.10.2026). Отложенную корзину без номера фискального чека, смены и розничного отчёта также исключить после проверки этих признаков.
  • Действующие операции со статусами «Архивный» и «Пробитый» учитываются наравне. Обычно заполнены номер чека и смена. Архивный документ без номера ККМ, но со ссылкой на отчёт о розничных продажах также учитывается; смена может быть заполнена или пуста. Его архивная группа сверяется с независимым отчётом по чекам. Другие неполные записи требуют проверки; автоматически удалять их нельзя.
  • Для архивного возврата со сменой и кассой, но без номера ККМ и ссылки на отчёт о розничных продажах, отдельно проверьте совпадение количества и сумм продаж и возвратов магазина со сводным отчётом (по полному либо архивному набору). При совпадении включите возврат один раз, со знаком минус в выручке и положительной суммой в колонке возвратов. Номер чека оставьте пустым.
  • Для операции «Продажа» сумму учитывать со знаком плюс, для «Возврат» — со знаком минус. Сама 1С может показывать положительную сумму в обеих строках.
  • Чеки без дисконтной карты участвуют в общих продажах и сверке, но не создают строки в итоговых «Бонусах».
  • Не удаляйте якобы дубли только по номеру чека: одинаковые номера возможны в разных кассах и сменах. Проверяйте вместе кассу, смену, номер чека и дату/время.

4.3. Полный список номеров и владельцев

  1. Откройте Маркетинг → Дисконтные карты. Точный альтернативный путь: e1cib/list/Справочник.ИнформационныеКарты.
  2. Через Ещё → Установить стандартные настройки сбросьте отборы и очистите поиск. Затем выберите Ещё → Режим просмотра → Список, чтобы вывести записи из всех групп.
  3. Выберите Ещё → Вывести список. Отметьте все колонки: Код, Наименование, Код карты, Владелец карты. Снимите «Только выделенные»; если присутствует «Включая подчинённые», включите её.
  4. Для ручного сохранения оставьте Табличный документ. После формирования откройте три точки в заголовке списка → Файл → Сохранить как… → Тип → Лист Excel2007-… (*.xlsx) → OK. Обычная кнопка «Сохранить» может сразу скачать внутренний формат .MXL. Программа использует этот путь XLSX для большого справочника «Марико-Мильстрим»; в остальных базах читает полный «Текстовый документ» с табуляцией.
  5. «Код карты» — номер карты для сопоставления с покупками. У старых записей поле может быть пустым, а номер сохранён в наименовании: принимайте точный формат «цифры (владелец)» только при совпадении имени с колонкой владельца; также подходит полностью цифровое наименование при заполненном владельце. Отметьте источник такого номера в справочнике. «Код» — внутренний код записи 1С. Не подменяйте одно другим. При переносе номера карты в Excel заранее задайте текстовый формат.
  6. Если чек содержит только наименование, сопоставьте его с колонкой «Наименование», затем получите номер. Если подходят несколько номеров, сохраните покупку один раз с исходным наименованием и пометкой «номер неоднозначен»; отметьте её как предварительную. Не выбирайте произвольный номер.

Номер карты — ключ. Если имя в старом чеке отличается от единственного имени в более свежем справочнике, используйте справочник. Полностью цифровое наименование также может дать номер при пустом владельце. При нескольких разных текущих именах одного номера дата изменения неизвестна: имя не выбирается наугад.

Пустой владелец в справочнике остаётся пустым. Разные номера с одинаковым именем остаются отдельными картами. Повтор одного номера и владельца объединяется. Если среди повторов номера только одно заполненное имя, используйте его. При нескольких разных заполненных именах в покупке оставьте только номер; в справочнике сохраните варианты с пометкой о конфликте. Запись с владельцем, но без номера карты, сохраните в справочнике с пустым номером и пояснением, не подставляя внутренний код. Полный справочник хранится отдельно в папке 1c-reports → Справочники карт, с датой обновления внутри файла. Обновляйте его раз в неделю и при появлении неизвестной карты в покупках. Отсутствие покупок за один день не означает, что карта никогда не использовалась.

Если в чеке ссылка на карту повреждена или объект не найден, не выдумывайте владельца и не теряйте сумму покупки: сохраните исходное представление карты, не подставляйте имя и отметьте случай для проверки.

4.4. Сборка итоговой таблицы

  1. Сгруппируйте действующие чеки с картой по дню + магазину + карте. В Excel это можно сделать сводной таблицей.
  2. Посчитайте сумму со знаком операции и количество строк-чеков. Возврат уменьшает сумму, но считается одним чеком.
  3. Присоедините номер и владельца из справочника. Итоговые пять колонок: Дата покупки; Дисконтная карта (номер + имя); Сумма по ДК; Количество чеков; Магазин. Телефон исключён. Карты без покупок в этот ежедневный файл не добавляются.
  4. Несколько покупок одной карты в одном магазине за день объединяются в одну строку. Та же карта в другом магазине — отдельная строка.

Сверка: отдельно сверяйте суммы и количества продаж и возвратов по магазинам. Если «Автовыгрузка - Чеки» включает только архивные чеки, сравнивайте с архивной частью журнала. В итоговые продажи и бонусы включайте также действующие «Пробитые». Общая сумма «Бонусов» не обязана совпадать с общей выручкой магазина, поскольку покупки без карт в неё не входят.

Повторный запуск

Проверенные ежедневные файлы повторно не создаются. Справочник используется до семи дней. Его новая версия заменяет прежнюю только после проверки; ID файла на Google Drive сохраняется. Карты связываются с покупками внутри одной базы, а не по совпадению имени между базами.

5. Сохранение и загрузка итогов

  1. Соберите три плоских XLSX с итоговыми колонками. В исходных отчётах остаются группировки и дополнительные итоги; простое переименование исходника не делает его итоговым файлом программы.
  2. Имена: 30.09.2026_Гроздь-Мильстрим_Продажи.xlsx, 30.09.2026_Гроздь-Мильстрим_Остатки.xlsx, 30.09.2026_Гроздь-Мильстрим_Бонусы.xlsx. Дата в имени — день данных.
  3. На Google Drive откройте папку 1c-reports. Найдите или создайте 2026.09_отчёты, внутри неё — 30.09.2026_отчёты и загрузите туда файлы.
  4. Если файлы с такими именами уже есть, сначала сравните данные. Не создавайте дополнительные копии без необходимости. Согласованная исправленная версия заменяет прежнюю через управление версиями файла Drive, сохраняя один файл.
  5. После загрузки проверьте названия, дату и содержимое. Полный день по девяти базам — 27 XLSX.

6. Если что-то мешает

  • «Потеряно соединение» — восстановите доступ, войдите заново и повторите незавершённую выгрузку с тем же периодом. Частичный файл не используйте.
  • Обычное уведомление проверки правомерности конфигурации можно отложить штатной кнопкой «Повторить позже», как вы разрешили. Если 1С всё равно блокирует работу, нужна проверка администратора.
  • Для HTTP-загрузки Chrome может потребоваться ваше подтверждение в панели загрузок. Не переименовывайте .crdownload в .xlsx.
  • Пустой отчёт сначала перепроверьте по дате, фильтрам и завершению формирования. Пустые данные не равны сбою формирования.
  • Не меняйте чеки, смены, документы поступления, карточки товаров и покупателей ради совпадения отчётов.
